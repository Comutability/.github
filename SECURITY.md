# Comutability Security Reporting
**Status: proposed default. Project-specific policies and private reporting channels take precedence.**

Please **do not** report undisclosed vulnerabilities, exploit details, leaked credentials or user data in a public issue or pull request.

For a project's vulnerability report:
1. Visit that project's **Security** tab and look for **Report a vulnerability** (GitHub private vulnerability reporting) if the maintainer has enabled it.
2. If that private channel does not exist, **do not publish details**; the community must provide an appropriate verified confidential reporting route before sensitive reports can be accepted.
3. Include affected version, impact and reproduction steps in the private channel, excluding unnecessary personal data.
4. Human maintainers will triage, coordinate fixes and communicate when safe. AI assistance does not count as independent security verification.

**Important:** No security inbox, dedicated response SLA or independent audit is currently asserted by this template. Do not claim a project is secure because its source is public.
