# Contributing to Comutability
**Status: proposed organisation-wide default; do not treat this text as ratified before its PR is reviewed.**

Comutability welcomes ideas, designs, documentation, translations, accessibility improvements, testing and code. **You do not need to join the GitHub organisation to contribute publicly.**

## Start here

- [Community Founding Charter](https://github.com/Comutability/Community/blob/main/FOUNDING-CHARTER.md) (approved)
- [Unified Operating Handbook proposal](https://github.com/Comutability/Community/pull/5)
- [Project and contributor guide](https://github.com/Comutability/Community/blob/proposal/unified-organisation-playbook-v0.1/docs/GETTING-STARTED.md)
- [Community issues](https://github.com/Comutability/Community/issues)

## Your contribution

1. Check the specific repository's README, licence and active maintenance status.
2. Search issues before filing a new one; describe the problem rather than guessing a solution.
3. For code, claim/confirm an issue with a maintainer, work on a feature branch or fork and open a PR.
4. Include documentation and tests appropriate to the change.
5. If you used **ChatGPT, Claude, Base44 or another AI tool** substantially, explain what it did and what you personally verified.
6. Never post API keys, personal data, unreleased security exploits or assets you lack rights to share.

## Review and membership

A human maintainer evaluates contributions for quality, accessibility, licence compatibility, privacy, security and maintainability. A PR is a proposal, not an obligation to merge. Named GitHub roles are invitation-only and limited to relevant projects.

Project-specific instructions override general workflow where compatible with the approved charter and licence. This file does not confer write access or waive legal obligations.
